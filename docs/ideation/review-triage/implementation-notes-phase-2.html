Implementation Notes — Phase 2

Review Triage · 2026-07-31 · Collapse selection, cap stats, and fixtures

selectCollapsible — a risk-signal veto the spec did not name

Context
The declared evidence set is three checkable facts, and one of them — no-external-callers — fires on any file with zero unchanged importers. Every brand-new file in a PR has zero unchanged importers, for the trivial reason that it did not exist on the base branch. Two of the five fixtures' ground-truth hotspots are new files (src/auth/token-validator.ts, src/cache/profile-cache.ts), so the literal three-check design collapses the single most important chapter in both.
Decision
Added isVetoed(): a file is eligible for collapse only when its FileRisk is quiet — no criticality keyword in its path, no test gap, and a risk entry present at all. Evidence answers "why is this boring"; the veto answers "is anything here shouting". The veto runs first and applies uniformly to all three evidence kinds, because one uniform rule is verifiable in a way three rules with exceptions are not. Verified non-vacuous by disabling the veto and re-running the gate: the safety test then fails with "auth-token-validation: collapsed chapter 0 hides hotspot src/auth/token-validator.ts". It also uses signals risk.ts already computes, so it adds no new numbers to tune — the size threshold the contract explicitly rejected.
Alternative
Rig each fixture's synthetic import index to give the hotspots callers. Rejected: it is a lie about a new module, and the safety gate would then be testing the index the test author wrote rather than the selection logic. A churn threshold was also considered and rejected for being exactly the tunable number the contract ruled out.

CollapseEvidence — no-external-callers carries files, not file

Context
The spec's union declares { kind: 'no-external-callers'; file: string; knownCallers: 0 } while the other two members carry files: string[]. But the all-files-agree rule means the evidence has to be true of the whole chapter, and the mechanical tail of the large fixture is one chapter over thirty caller-free components. A single file field there names one of thirty and reads as a complete claim.
Decision
All three members now carry files: string[]; no-external-callers keeps knownCallers: 0. The union stays closed, which is the property the decision log actually argued for. Reason strings adapt to the count: "src/utils/format.ts has 0 known callers outside this PR" for one file, "30 files, 0 known callers outside this PR" for many. Downstream contract: Phase 3 mirrors this type by hand in packages/web/src/state/types.ts and must mirror files. The Stretch caller-list disclosure is unaffected — it reads Phase 1's persisted caller list on non-collapsed chapters, not this field.
Alternative
Keep file: string and populate it with the chapter's first file. Rejected: the reason line would be true and the evidence object would not, which is the failure mode the closed union exists to prevent.

dividerBefore — withheld when the collapsed set is not a contiguous suffix

Context
The spec defines dividerBefore as the lowest collapsed index and Phase 3 draws one divider there. Nothing enforces that collapsed chapters sit at the end: risk-descending chapter order is a prompt instruction (prompt.ts:239) that eval/judge.ts:215 records as a baseline boolean rather than asserts, and collapse evidence is orthogonal to the model's risk label anyway. A caller-free chapter at index 1 with a high-risk chapter at index 3 would put an expanded chapter below the collapsed boundary.
Decision
resolveDivider() returns the lowest collapsed index only when every chapter from there to the end is collapsed, and null otherwise. decisions stays authoritative for which chapters collapse; dividerBefore is only the rendering hint, and it exists only when one line can honestly represent the boundary. Covered by "withholds the divider when the collapsed chapters are not a contiguous suffix". In the contiguous case this is identical to the spec's rule, so Phase 3's dividerBefore === idx check is unchanged.
Alternative
Reorder chapters so the collapsed ones form a suffix. Rejected by the contract — chapters are not reordered — and it would break the readingPlan chapter indices too.

filesScanned === 0 disables every evidence kind, not just the caller check

Context
The spec requires an explicit filesScanned === 0 guard producing no decisions. Two of the three evidence kinds (test-only, generated) are path-only and would still be answerable from a broken index.
Decision
The guard returns { available: true, decisions: [], dividerBefore: null } before any chapter is examined. Answering some of a narrative's chapters from an index that never got built is how a partial failure reads as a complete answer. It returns the available variant rather than a fabricated unavailable reason, because the snapshot layer already owns that mapping ('empty-tree') and this path only exists for the case where an inconsistent context arrives anyway.
Alternative
Let the path-only kinds still fire. Rejected: a reviewer cannot tell which chapters were assessed and which were skipped, and the divider would imply the whole list was.

Recorded narratives — hand-authored, with mechanically derived section ranges (Open Item resolved)

Context
The spec's Open Item asks whether the five recordings come from real generations. There is no recording mechanism: eval/run.ts persists only a scored Baseline, never the narrative. A real large-refactor generation is also a two-pass run with one writer call per theme, i.e. real provider spend, and no provider is configured here.
Decision
All five are hand-authored, and each carries a _provenance string at the top of the JSON saying so (normalizeNarrative ignores unknown fields). Every diff section's startLine/endLine/hunkIndex was derived mechanically from the fixture's own hunks — new-side extent, old-side for deletion-only hunks, the same rule writer.ts's hunkRange uses — so a range here cannot disagree with the fixture it points at. The recorded test re-checks that invariant: every referenced file is in the fixture, every hunkIndex is in range, and no range is reversed. Deliberately not generated from buildSuppressedChapter-style themes, which hardcode startLine: 1, endLine: 1 and would make the compression floor unreachable for reasons unrelated to the implementation.
Alternative
Lift narratives out of a warm ~/.cache/diffdad narrative cache file. Rejected: the cached shapes are for unrelated PRs, so the fixtures' expectedHotspots would have nothing to bind to, and the compression gate needs a recording of this fixture.

auth-token-validation — the adversarial recording, and what it actually catches

Context
The spec requires one recording where the hotspot sits in a chapter that looks collapsible by the other signals, so the safety test cannot pass by accident.
Decision
Chapter 0 holds src/auth/token-validator.ts (the hotspot) together with src/worker/queue.ts, which carries no criticality keyword, and the chapter's own risk label is "low". Because the validator is a new file, it has zero known callers once the diff's own files are excluded — so the caller signal alone would collapse it. Only the risk-signal veto keeps it open, which is stated in the file's _provenance and confirmed empirically: with the veto removed the safety test fails on exactly this chapter.
Alternative
Put the hotspot in an obviously high-risk chapter. Rejected by the spec, and it would make the safety assertion pass without exercising anything.

large-refactor — 43 files, with the mechanical tail generated rather than spelled out

Context
The existing fixtures spell every DiffLine literally: 201 lines of source for three diff files. At 43 files that is two to three thousand lines of near-identical object literals.
Decision
A local oneHunkFile(path, markers) helper walks unified-diff marker tuples into DiffLines with correct old/new numbering. The three hotspots are still written out line by line — their content carries the meaning the ground truth refers to — and only the thirty-component rename and eight spec files are generated. Constraints the tail respects, each for a specific reason: no dist/-style paths (partitionMechanicalFiles drops those before the planner runs, so a real narrative would have no chapter for them at all); unique basenames (callersOf buckets by basename, so a repeated index.tsx would move the ratio for unrelated reasons); no criticality keywords in component names (a mechanical file that trips the veto stops being mechanical); and an adjacent __tests__/ directory so the thirty components do not all report a test gap. Measured before the assertion was written: 398 of 533 narrated diff lines collapse, a ratio of 0.747 — comfortably over the 0.4 floor and under the 0.9 ceiling the test also asserts, so the three hotspot chapters genuinely stay open.
Alternative
Spell out all 43 files. Rejected: a fixture nobody will read is a fixture nobody will notice is wrong, and the generated half is the half where every entry is identical anyway.

The synthetic import index is an authored artifact, and it is declared as one

Context
selectCollapsible needs risks and a RepoContext. Neither a recording nor an EvalFixture carries either, and the spec never says where they come from. Whether the safety and compression tests do any work is decided by that missing input.
Decision
REPO_CALLERS in collapse.test.ts declares one caller map per fixture, keyed by module basename (what callersOf looks up), with the omissions documented inline: profile-cache has no entry because zero callers is the honest answer for a new module, and retry-policy has one because its unchanged callers are the only thing holding that chapter open. risks is always computeRisk(fixture.files, repo) — never hand-built — so the tests read the same inboundScope: 'repo' signals production produces. The implementation never reads FileRisk.inboundRefs for the caller question either: that number is total centrality including importers inside the PR, so callers are derived from repo.index via callersOf(..., changedFiles), which also makes a risks/repo scope mismatch unable to cause a wrong collapse.
Alternative
Extend EvalFixture with a caller map. Rejected: it is test scaffolding, not fixture ground truth, and the eval harness has no use for it.

recordedNarrativePath is absolute, built from import.meta.url

Context
The field exists "so tests and the harness resolve recordings the same way", and the two run from different working directories — bun test from wherever it was invoked, bun run eval from the repo root. A cwd-relative path resolves differently for each, which is the bug eval/run.ts:170 already has.
Decision
Each fixture builds its own absolute path with fileURLToPath(new URL('./recorded/<id>.narrative.json', import.meta.url)) — one resolution rule, no shared helper module, and fileURLToPath rather than .pathname so a percent-encoded path segment does not break it. Safe for build:bin: cli.ts does not import eval/, so none of this is bundled into the compiled binary.
Alternative
Store the basename and resolve it in each consumer. Rejected: two consumers means two resolution rules, which is the thing the field exists to prevent.

Cap-stats plumbing — PlannerResult.stats is required, capStats is optional

Context
buildPlannerPrompt already returns stats and runPlanner dropped it. NarrativeGenerationResult had nowhere to put it.
Decision
PlannerResult.stats is non-optional — the planner always builds a prompt, so an optional field there would invite a ?? {} somewhere downstream. NarrativeGenerationResult.capStats is optional and left undefined on the plan-cache-hit branch, where no prompt was built and plannerProvider stays 'cached'. The single-pass path returns the stats it already destructured for logPromptStats. All six existing generateNarrative call sites either destructure { narrative } or read named fields, so the addition is inert until Phase 3 reads it.
Alternative
Default capStats to an empty PromptCapStats on a cache hit. Rejected by the spec's own failure-mode table: "unknown" and "nothing was truncated" must not render alike, or the UI claims a partial story is complete.

generated evidence is reachable only from outside the narrative pipeline

Context
generateNarrative calls partitionMechanicalFiles first, which drops everything classifyPath flags before the planner sees it. Path-classified files therefore never appear in a chapter produced by this pipeline, so the generated evidence kind cannot fire on a real narrative.
Decision
Kept the kind, implemented via classifyPath (the only path-only check available to a pure function — classifyFile's @generated-header detection needs a DiffFile, which selectCollapsible does not have), and covered by unit test only. It exists for chapters that arrive from a different producer — a watch-mode or daemon path that does not partition first — and costs one every() call. Recorded here so a future reader does not mistake the missing production coverage for an oversight.
Alternative
Drop the kind. Rejected: it is part of the declared union Phase 3 renders, and removing a member of a closed union is a downstream contract change for a saving of three lines.
