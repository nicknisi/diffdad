## Conventions

### Phase 3 additions

- **Web tests are pure-logic `.ts`, never component `.tsx`.** All 11 files under `packages/web/src/{lib,hooks,state}/__tests__/` test exported functions and store actions: `walkthrough.ts`, `units-view.ts`, `unit-gate`, `anchor`, `file-tree`, `microcopy`, `theme`, `config-client`, `config-actions`, `durable-review-state`, and `useLiveStream` (via the exported `handleNarrativePartialEvent`/`handleUnitCommentEvent` rather than by mounting the hook). The house answer to "test this component" is to export the decision function and test that. `useLiveStream.test.ts:1` imports the handlers directly — the pattern to copy for precedence logic.
- **Web tests import from `'vitest'`** and run via `bun run --filter '@diffdad/web' test` → `vitest run` (no config block, node environment, no setup files). The CLI's flat `packages/cli/src/__tests__/` runs under `bun test`; the two suites never mix.
- **Web components take store state, not props.** `StoryView` (`:239-255`) and `Chapter` (`:179` `storyStructure`, plus `useReviewStore` reads throughout) subscribe with selectors. `Chapter`'s only props are the three at `:13-18`, all passed by `StoryView`. New cross-cutting data becomes store state; new per-chapter data becomes a prop.
- **Local sub-components over new files.** `StoryView.tsx` already holds `OrphanedInlineComments`, `Discussion`, `RegeneratingBanner`, `OtherConcerns`, and `formatElapsed` in-file. `CollapseDivider` and both banners belong there, matching the spec.
- **Colors via CSS custom properties in `style={{}}`**, never Tailwind color classes (CLAUDE.md is explicit, and every banner/pill in `Chapter.tsx`/`StoryView.tsx` follows it). Sizes are bracketed arbitrary values (`text-[12.5px]`, `rounded-[10px]`).
- **`return null` for the inactive state.** `RegeneratingBanner:191`, `OrphanedInlineComments:70`, `Discussion:123`, `OtherConcerns:215`, `Overview:85`. The "nothing renders when `dividerBefore` is null" requirement is the established idiom, not a new one.
- **Numbers are `toLocaleString()`'d** in UI copy (`StoryView.tsx:208`, `snapshot.ts:504`). The divider's "1,180 lines" should follow.
- **Daemon capabilities are optional closures on `GitHubWiring`**, read at request time via `wiring.current.X` and never destructured at construction (`app.ts:54-55` states the invariant explicitly, and `:193,249,301,314,368,487` all obey it).
- **Route handlers 503 rather than pretend** when a capability is absent (`app.ts:195`, `:302`, `:315`). A missing repo-context resolver should degrade to `{available:false}` instead, since the notice is exactly the "we could not tell you" state.

## Risks

### Phase 3

- **The mandated web test files cannot run in this repo as configured.** `packages/web/vite.config.ts` has no `test` block, `vitest run` reports `environment 5ms / setup 0ms` (node), and `jsdom`, `happy-dom` and `@testing-library/react` are all absent from `node_modules` — they are vitest _optional peers_ (`bun.lock:1768`), never installed. `collapse-render.test.tsx` and `chapter-precedence.test.tsx` need a DOM plus a renderer, so the spec's own inner-loop command cannot execute its own required tests. Three resolutions, none chosen by the spec: (a) add `happy-dom`/`jsdom` + `@testing-library/react` devDeps and a `test: {environment}` block — new deps, a lockfile change, and two files outside the Modified Files list; (b) `react-dom/server`'s `renderToStaticMarkup`, which needs no DOM and covers divider placement, the notice, and the initial seed, but **cannot** cover "expand it, then mark it reviewed, and it must not re-collapse"; (c) extract the precedence and divider rules into a pure `lib/` module and test them as `.ts`, which is what every one of the 11 existing web test files does. Decide before writing either file.
- **`storyStructure` has three values and only one of them collapses.** `Chapter.tsx:491` (`outline`) and `:530` (`linear`) never read `collapsed`; the default `'chapters'` (`review-store.ts:447`) is the only branch with the boundary. A reviewer on the outline or linear structure sees no reason line and no collapse at all, while `StoryView` still draws the divider. Either gate the divider on `storyStructure === 'chapters'` or render the reason in all three branches.
- **`useState` seeds once, and on the streaming path the decision arrives after mount.** The spec forbids a second effect that writes `collapsed` ("Seed once in `useState`"), which is right for the state fight — and it means a collapse decision that lands _after_ the chapter mounted is silently ignored. That is the normal case for regeneration: `applyPlan` (`review-store.ts:728-745`) paints placeholder chapters with `sections: []`, then the `narrative` SSE event (`useLiveStream.ts:219`) replaces them, and `key={ch-${idx}}` is unchanged so React reuses the same component instances. Expect collapse to work on first load and do nothing after a regenerate; decide whether that is acceptable or whether the divider alone carries the boundary in that case.
- **Stale `chapterIndex` after a plan swap.** `CollapseDecision.chapterIndex` indexes the chapter array that existed when the server computed it. `applyPlan` replaces `chapters` wholesale, and the store already documents this exact hazard for reviewed-state: "carrying `ch-${idx}` entries across a plan that reorders chapters would transfer 'reviewed' to the wrong chapter" (`review-store.ts:742-744`). Collapse must be cleared on `applyPlan` and on any `setData` that does not carry a fresh `collapse`, or the reason line will describe the wrong chapter.
- **`capStats` is unreachable in the daemon without persisting it.** `daemon.ts:269` destructures `{ narrative }` and discards `capStats`; `store.attachReview` (`:277`) has no parameter for it; `ReviewUnit` has no field. Generation happens in a poll/hydrate that has already returned by the time `GET /api/units/:id` runs, possibly in a previous process. So the truncation banner cannot appear in the drill-in — which the spec's own manual test demands ("confirm parity with the CLI review") — unless `capStats` is persisted on the unit. Note this is **not** the staleness defect the decision log forbids: `capStats` describes the generation that produced that narrative, so it is valid exactly as long as the narrative beside it is. The spec's `units/types.ts` row says "No collapse fields" and is silent on `capStats`; treat that silence as the gap it is rather than as a prohibition.
- **`capStats` is also unreachable in the CLI as the file list stands.** `cli.ts:386-388` reads `result.narrative` and `result.provider` and drops `result.capStats`, `ServerContext` (`server.ts:21-39`) has no field for it, and `/api/narrative` never calls `generateNarrative`. `cli.ts` is not in the Modified Files list, so the `promptCapStats` test the spec requires would pass against a field nothing ever populates in the real `dad review` path.
- **Resolving repo context inside a GET can block the response for a full tarball download.** `resolveRepoContext` (`snapshot.ts:409-489`) is a cache read when warm and a whole-repository fetch, extract, and index when cold; it never throws, but it can be slow. Doing it in `/api/narrative` or `GET /api/units/:id` puts that latency in front of the first paint. The CLI already has a warm context at `cli.ts:305`; the daemon has the Stretch prefetch for the same reason, which means the non-stretch daemon path is the slow one. Consider serving `{available:false}` on a cold miss and letting the prefetch warm it, rather than awaiting.
- **`app.ts` has no GitHub client, so the daemon route cannot resolve context by itself.** `DaemonAppDeps` (`:105-120`) carries `store`, `hub`, `wiring`, `ai`, `onConfigChange`, `webDist`; `GitHubWiring` (`:61-103`) carries only closures. A new **optional** wiring member is required (`buildGitHubWiring`, `daemon.ts:155-173`, is the seam, and `makeStatusFetcher:339-350` the shape). Making it required breaks the dark-daemon path (`daemon.ts:161`) and both test harnesses (`units-routes.test.ts:89-99`, `daemon-rewire.test.ts`).
- **The unavailable notice has four reasons, and the spec's copy names two.** `CollapseUnavailableReason` resolves to `'size-cap' | 'fetch-failed' | 'extract-failed' | 'empty-tree'` (`collapse.ts:39` via `snapshot.ts:23`). The spec's key decision gives copy for `size-cap` and `fetch-failed` only. `empty-tree` was added in Phase 1 precisely so "nothing imports this" and "no index" never render alike, and Phase 1's own map flagged that "Phase 3 must render it". Mirror `UNAVAILABLE_REASON_TEXT` (`snapshot.ts:491-496`) as a `Record` so a fifth reason is a type error.
- **Banners live in `StoryView`, but the Files tab does not render `StoryView`.** `App.tsx:172-190` and `UnitReview.tsx:377-379,424,429` switch between `StoryView`, `ClassicView` and `RecapView`. Truncation is a fact about the whole review — the diff on screen is partial — so hiding it behind one tab is the more serious of the two banners disappearing in the view where the reviewer is reading raw files. `Chapter`'s `outline`/`linear` structures keep `StoryView`, so only the tab switch loses it.
- **`narratedDiffLines` cannot be imported by the web.** The spec's step 4 says to compute the collapsed line count "with the `narratedDiffLines` helper Phase 2 exposed", but that helper is `packages/cli/src/narrative/collapse.ts:199`, and `packages/web` has **zero** imports from `packages/cli` (verified) — the whole reason `NarrativeResponse` is mirrored by hand. Either the server sends the number alongside `collapse`, or the web keeps a local copy of the five-line reduction over `sections` (with the `Math.max(0, ...)` clamp, which exists because section line numbers are model-authored and validated only as numbers).
- **`available: true` does not imply anything to render.** `collapse.ts:171` returns `{available:true, decisions:[], dividerBefore:null}` when `filesScanned === 0`, and `resolveDivider` returns `null` whenever the collapsed set is not a contiguous suffix — so a chapter can carry a decision (and show a reason line) while no divider exists. Derive the divider strictly from `dividerBefore !== null` and the notice strictly from `available === false`; neither from `decisions.length`.
- **The Stretch caller-list disclosure rests on two things that do not exist.** It says to "include the caller paths on the risk payload the server already sends" and to "add a disclosure to the evidence line in `Chapter.tsx`". There is **no risk payload** — `rg` for `risks|FileRisk|inboundRefs|inboundScope|criticality` across `packages/web/src` returns nothing — and there is **no evidence line** in `Chapter.tsx` until this phase adds the reason line. `CollapseEvidence.files` (which Phase 2's notes require the mirror to carry) lists the chapter's own files, not their importers, so the caller paths are genuinely new payload from `callersOf(repo.index, file, changedFiles)`. Treat the Stretch as new plumbing, not a read of something already wired.
- **`PromptCapStats` carries full path lists.** `droppedFiles: string[]` and `truncatedFiles[].file` mean the banner's payload grows with the dropped set on exactly the giant PRs that trigger it. The banner needs two counts; sending the arrays is harmless on localhost but only the counts are load-bearing.
- **Decision-log check: premises hold, with two spec-internal contradictions rather than codebase drift.** Verified against the tree: (1) collapse is evidence-gated with no PR-size gate anywhere in `selectCollapsible` — sound; (2) nothing persists collapse, and `narrativeCachePath` (`cache.ts:45-48`) still has no repo-state component — sound, and the extension to `ReviewUnit` is sound for _collapse_ while being wrong-by-omission for `capStats` (see above); (3) chapters are not reordered — `StoryView.tsx:269` still renders `narrative.chapters` in order, and `Overview.tsx:66-76` still documents the chapter table as "the reading plan (planner order = risk descending)", so pulling `readingPlan` from the UI remains true (no component renders the array); (4) repo context comes from cached tarballs with an explicit unavailable state — sound, except that the decision's own reason describes the notice as "a size cap or a failed fetch", which under-counts the union by two members; (5) compression is measured in narrated diff lines — sound, though the divider copy in the spec states both chapters and lines, and the helper that produces the line count is on the wrong side of the package boundary.
- **`bun run format:check` is already red, on 9 ideation docs, not on code.** Verified: `context-map.md`, `contract.{md,html}`, `implementation-notes-phase-{1,2}.html`, `spec-phase-{1,2,3,4}.md`. oxfmt covers `.md` and `.html`, and CI runs `format:check` as its own job. A blanket `bun run format` will rewrite the spec being implemented from; format the added files specifically.
