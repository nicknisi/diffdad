Implementation Notes — Phase 4

Review Triage · 2026-07-31 · Deterministic hotspot placement scoring in the eval harness

Harness reporting — runOne has no CollapseResult to pass

Context
The spec says "call scoreHotspotPlacement in runOne", but runOne holds no collapse decisions, no RepoContext and no FileRisk[], and it cannot resolve one: resolveRepoContext needs an owner/repo and PRMetadata carries neither, because a fixture is a synthetic PR. The harness also calls generateNarrative without options.repoContext.
Decision
Pass a named module constant NO_COLLAPSE = { available: true, decisions: [], dividerBefore: null } with a doc comment stating the consequence plainly: expanded equals covered for every harness run, so what the probe reports is hotspot coverage. The expanded-versus-collapsed distinction is exercised by the unit tests and by the served path instead. Stating it beats letting a reader infer agreement from two booleans that are provably equal.
Alternative
{ available: false, reason: 'fetch-failed' } — same numbers, but it claims a fetch that never happened had failed. Or moving collapse.test.ts's authored REPO_CALLERS table into the fixtures so runOne could run selectCollapsible for real — the only route where expanded measures something, rejected because it re-authors fixture data this phase's decision log explicitly assigns to Phase 2, and touches files outside the spec's list.

Harness reporting — run.ts had to become import-safe first

Context
The spec's only instruction was "export aggregate". run.ts ends in a bare void main(); and had zero importers, so nothing had caught it. Exporting alone would mean the new test's import runs the whole harness inside bun test: all five fixtures, readConfig(), a real provider call per fixture, and a written packages/cli/eval-baseline/baseline.json in a directory that is not gitignored.
Decision
Guard it as if (import.meta.main) void main();, following the one existing precedent at cli.ts:554. Verified after the fact that packages/cli/eval-baseline/ does not exist following a full bun run test.
Alternative
Extracting aggregate into a separate module so run.ts stays a pure script. Rejected: it adds a file the spec does not name, and the guard is one line that also fixes the latent hazard for every future importer.

Harness reporting — macro average, not pooled counts

Context
The spec describes avgHotspotPlacement two ways in one sentence: "the fraction of scored hotspots that landed in expanded chapters" (pooled) and "over runs with status: 'scored' only" (per-run). The two disagree, because large-refactor declares three hotspots and the others declare one.
Decision
Macro: filter to scored runs, then average their per-run ratios, rounded with Number(avg(...).toFixed(2)) and defaulting to 0. That is exactly the shape of avgDefectRecall two lines above it, and consistency with the field it sits beside is worth more than either reading. expandedOf keeps the raw counts on every run, so a pooled number is still recoverable from a baseline.
Alternative
Pooled Σexpanded / Σtotal, which would let the one three-hotspot fixture outweigh the three single-hotspot ones. The aggregate test pins the macro value at 0.67 and asserts it is neither 0.5 (pooled) nor 0.44 (n/a averaged in as zero).

Placement scoring — the unavailable arm of CollapseResult

Context
CollapseResult is a two-arm union and the spec only describes the available one. The available: false arm has no decisions field at all, so "is the covering chapter collapsed" has no direct answer there.
Decision
Read unavailable as nothing collapsed, so a covered hotspot is an expanded one — which is what selectCollapsible actually does, short-circuiting on that arm before weighing any evidence. Written as an explicit ternary producing an empty set, not a ?? [] default, so the claim is stated rather than reached by a narrowing accident, and pinned by its own test.
Alternative
Returning status: 'n/a' when collapse is unavailable. Rejected: coverage is still perfectly measurable without a repo snapshot, and n/a there would silence the metric for every run the harness produces.

Placement scoring — a generation failure reports n/a, not zero

Context
runOne's catch branch returns a fully-formed EvalRun after a generation failure, with scores zeroed. A required hotspotPlacement forces that site to produce a value with no narrative in hand, and the spec does not say which.
Decision
A module constant HOTSPOTS_UNSCORED with status: 'n/a'. A scored zero there would drag avgHotspotPlacement down on every provider outage — the same "n/a averaged as zero" failure the spec's own table names for safe-rename, arriving through a second door.
Alternative
status: 'scored' with expanded: 0 over the declared hotspots, which reads as "the narrative missed all of them" when no narrative exists.

Harness reporting — eval/README.md touched outside the spec's file list

Context
The README's "What it measures" section enumerates every number the harness reports, and it is not in the spec's Modified Files. Adding a reported metric without a line there leaves the folder's own documentation stale.
Decision
Four lines under "What it measures", covering the metric, that it is deterministic with no judge call, and that n/a fixtures are skipped rather than scored as a miss.
Alternative
Leaving it out to keep the diff inside the spec's declared file list.

Testing — the interesting cases had to be built, not loaded

Context
The spec's experiment asks for an uncovered hotspot and for paths differing only by an a//b/ prefix. Neither exists in the committed data: every recording covers its fixture's hotspots (that is the point), and every recorded section file and every expectedHotspots entry is already a bare path.
Decision
Real recordings for the covered/collapsed/multi-hotspot/n-a cases; synthetic inputs for the two that cannot come from a fixture — a narrative with the hotspot's diff sections stripped (plus a prose section naming the file, to prove prose is not coverage), and a hand-built b/-prefixed narrative against an a/-prefixed ground truth.
Alternative
Driving those two cases off fixtures anyway, which would produce a test named for the prefix trap that asserts nothing about it.
